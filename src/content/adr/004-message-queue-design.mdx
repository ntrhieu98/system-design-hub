## Bối cảnh

Cần async communication giữa services với:
- Decoupling producer và consumer
- Buffering traffic spikes
- High throughput
- Reliability (retry, DLQ)
- Delivery guarantees

## Yếu tố quyết định

### 1. Message Broker
**Quyết định:** Kafka cho event streaming, RabbitMQ cho task queues

**So sánh:**
| Feature | Kafka | RabbitMQ | SQS |
|---------|-------|----------|-----|
| Throughput | Millions msg/sec | Thousands msg/sec | Managed |
| Model | Distributed log | Message broker | Managed queue |
| Retention | Configurable | Until consumed | Until consumed |
| Ordering | Per-partition | Per-queue | FIFO option |
| Replay | Yes | No | No |
| Complexity | High | Medium | Low |

**Chọn Kafka khi:** Event sourcing, analytics, large-scale, need replay
**Chọn RabbitMQ khi:** Task queues, RPC patterns, flexible routing

### 2. Delivery Guarantee
**Quyết định:** At-least-once với idempotent consumers

**Các guarantees:**
- **At-most-once**: Fire-and-forget, có thể mất messages
- **At-least-once**: Ack + retry, có thể duplicate → consumer idempotent
- **Exactly-once**: Transactional outbox + dedup, phức tạp

**Chọn at-least-once vì:** Balance giữa reliability và complexity. Exactly-once requires distributed transactions.

### 3. Idempotency
**Quyết định:** Idempotency keys cho critical operations

**Implementation:**
- Store (idempotency_key → result) mapping
- Check before processing
- Return cached result if duplicate

### 4. Backpressure Handling
**Quyết định:** Bounded queue + consumer scaling

**Strategies:**
- Bounded queue: Max size, reject/drop when full
- Rate limiting producer: Throttle based on queue depth
- Consumer auto-scaling: Scale based on queue lag
- Dead letter queue: Failed messages → DLQ for inspection

### 5. Message Ordering
**Quyết định:** Per-partition ordering (Kafka) hoặc per-queue (RabbitMQ)

**Trade-off:** Ordering vs throughput (single partition = ordered but limited throughput)

## Hệ quả

### Tích cực
- Decoupling services
- Buffering traffic spikes
- High throughput
- Resilience (retry, DLQ)

### Tiêu cực
- Complexity (ops, monitoring)
- Eventual consistency
- Debugging khó hơn (async flows)
- Message ordering challenges

### Rủi ro
- Message loss nếu không ack đúng
- Duplicate processing nếu consumer không idempotent
- Poison messages blocking queue
- Queue overflow nếu consumer chậm
